# Polarfield (fuzzion, 2010)

Source code of *Polarfield*, a 4k intro released by fuzzion in 2010, together
with a platform-independent rewrite of its core and native ports for macOS and
the web.

The original was a Win32 executable built on top of fixed-function OpenGL and DirectSound.
 This repository keeps those sources untouched next to a cleaned-up C99 core that produces the same images and the same music, so the intro can run on today's platforms.

## Repository layout

```
original/            the 2010 sources exactly as released
common/              platform-independent core shared by every port
  polar.h            public API used by the ports
  polar_math.h       matrix stack / trig / LCG replacing the x87 inline asm
  polar_scene.c      geometry generation (parametric horns, cubes, Fourier logo, text)
  polar_render.c     drawing + GPU-instanced ambient occlusion bake
  polar_synth.c      the synth and the tracker sequencer, rendered to PCM
  polar_gl.h         picks the GL header (OpenGL 3.3 core / GLES 3 / WebGL2)
  glyphs.h           pre-tessellated glyphs (generated by tools/gen_glyphs.py)
ports/
  mac-x86_64/        Cocoa + OpenGL 4.1 core + CoreAudio, no dependencies
  web/               WebAssembly + WebGL2 + Web Audio via Emscripten
docs/
  index.html         single-file build of the web port, ready for GitHub Pages
tools/
  gen_glyphs.py      TTF -> glyphs.h (fonttools + mapbox_earcut)
  capture_mac.c      headless frame/WAV capture, useful to check the core
```

## Building

### macOS

Requires Xcode command line tools. Builds for x86_64 by default; pass
`ARCH=arm64` for a native Apple Silicon binary.

```sh
cd ports/mac-x86_64
make            # build/polarfield
make run        # windowed; ESC quits, pass --fullscreen for full screen
make capture    # build/capture <out_dir> <ms>... writes PNG frames and song.wav
```

### Web

Requires [Emscripten](https://emscripten.org/docs/getting_started/downloads.html)
(`emcc` on the PATH, e.g. `brew install emscripten`).

```sh
cd ports/web
make            # build/index.html + index.js + index.wasm
make serve      # http://localhost:8080  (WebGL2 needs an http origin, not file://)
make docs       # ../../docs/index.html with JS and wasm inlined in one file
```

The page shows a click-to-start overlay because browsers only start audio
after a user gesture.

### Regenerating the glyphs

Only needed if the text or the font changes.

```sh
pip install fonttools mapbox_earcut
python3 tools/gen_glyphs.py tools/LiberationSans-Bold.ttf common/glyphs.h
```

## How the port works

The original relied on three things that don't exist outside Win32 / OpenGL
1.x. Each was replaced by something that produces the same numbers.

**Fixed-function matrix stack.** `glRotatef`/`glTranslatef`/`glScalef` and
`glGetFloatv(GL_MODELVIEW_MATRIX)` drove the geometry generation.
`polar_math.h` implements the same column-major post-multiplying stack, plus
`gluPerspective`/`gluLookAt`. Quads are emitted as two triangles.

**Ambient occlusion bake.** For every vertex of the high-res scene the
original pointed a 70 degree camera along the vertex normal, drew the low-res
scene black-on-white into a 64x64 viewport, and averaged the pixels with
`glReadPixels` (about 170k tiny render + readback round trips).
`polar_render.c` does the same with instancing: each instance builds its own
look-at matrix in the vertex shader and is squeezed into a 64x64 tile of a
2048x2048 texture, a reduction shader sums each tile, and one small
`glReadPixels` returns 1024 averages at a time. The colour formula
`sum / (64*64*256)` is the original's. The bake takes a couple of seconds on
a desktop GPU; the loading screen and loading music play meanwhile, as they
did in 2010.

**Font outlines.** `wglUseFontOutlines("Arial Bold")` produced polygonal
text at runtime. `tools/gen_glyphs.py` tessellates the 21 glyphs the intro
uses from Liberation Sans Bold (SIL OFL, metric-compatible with Arial) into
`common/glyphs.h`. The text becomes part of each scene's mesh, drawn black
and acting as an occluder in the bake exactly like before.

**Music.** `mzk.c` generated 8 samples with a small subtractive synth into
64 DirectSound buffers, and a thread ticked an 8-channel pattern sequencer
every 110 ms. `polar_synth.c` runs the same synth (same tables, same LCG
noise) and a software mixer that plays the same sequencer offline into a
float PCM buffer. The ports stream that buffer, and the visuals derive the
`order` value from the audio clock the same way the sequencer thread did.
The mix clips like the 8-bit DirectSound primary buffer did.

The web port compiles the same core to WebAssembly and renders through
WebGL2, so the GLES 3.0 calls map 1:1. Only `ports/web/main_web.c` and
`shell.html` are browser specific: context creation, the
requestAnimationFrame loop, and a few `EM_JS` functions that hand the PCM
buffer to Web Audio. There is a single source of truth for geometry, bake and
synth, so every port looks and sounds identical, and a new platform only
needs a new file in `ports/`.
